# مساعدك الرقمي للخدمات الإلكترونية

مشروع واجهة عربية RTL مبني على Next.js 15 وReact 19 وTypeScript، مع Supabase للمصادقة وقاعدة البيانات وتخزين المرفقات.

## محتويات المشروع

- `app/`: الصفحات العامة وصفحات حساب العميل ولوحة الإدارة.
- `components/`: الترويسة والتذييل ومكونات الواجهة المشتركة.
- `lib/supabase.ts`: تهيئة اتصال Supabase من متغيرات البيئة.
- `public/images/`: الشعار وصور الواجهة والخدمات.
- `database.sql`: مخطط قاعدة البيانات الموحد وسياسات RLS والتخزين والإشعارات والفواتير والمدفوعات.
- `.env.example`: نموذج متغيرات الاتصال.

## 1. إنشاء قاعدة البيانات

1. أنشئ مشروع Supabase جديداً أو استخدم قاعدة فارغة لم يسبق تشغيل مخطط مختلف عليها.
2. افتح **SQL Editor** ثم **New query**.
3. افتح `database.sql` وانسخ محتواه كاملاً إلى المحرر.
4. اضغط **Run** وانتظر رسالة نجاح التنفيذ.
5. لا تشغّل ملف SQL فوق قاعدة إنتاج فيها بيانات قديمة قبل أخذ نسخة احتياطية ومراجعة ترحيل المخطط.

## 2. إعداد مفاتيح Supabase

من إعدادات مشروع Supabase انسخ Project URL والمفتاح العام (Publishable key أو anon legacy key). أنشئ ملف `.env.local` في جذر المشروع:

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_OR_ANON_KEY
```

لا تضع `service_role` أو `secret key` في ملف يبدأ بـ `NEXT_PUBLIC_`، ولا ترفع `.env.local` إلى GitHub.

## 3. النشر عبر GitHub وVercel

1. أنشئ مستودع GitHub فارغاً.
2. ارفع **محتويات** هذا المجلد إلى جذر المستودع، بحيث يكون `package.json` في المستوى الأول، وليس داخل مجلد إضافي.
3. في Vercel اختر **Add New → Project** ثم استورد مستودع GitHub.
4. اترك Framework على Next.js وRoot Directory على `./`.
5. أضف متغيري البيئة السابقين في Vercel لبيئات Production وPreview وDevelopment.
6. اضغط Deploy.

## 4. إعداد روابط المصادقة

بعد معرفة رابط Vercel:

1. افتح Supabase → Authentication → URL Configuration.
2. ضع رابط الموقع الفعلي في Site URL.
3. أضف رابط إعادة التوجيه للموقع ضمن Redirect URLs، مثال:

```text
https://YOUR-VERCEL-DOMAIN.vercel.app/**
```

استبدل النطاق بالمجال الحقيقي الذي أعطاك Vercel.

## 5. إنشاء حساب المدير

1. افتح الموقع المنشور وأنشئ حساباً عادياً بالبريد الذي سيستخدمه المدير.
2. إذا كان تأكيد البريد مفعلاً، أكّد البريد أولاً.
3. في Supabase SQL Editor نفّذ الأمر التالي مع بريد المدير الحقيقي:

```sql
UPDATE public.profiles
SET role = 'admin'
WHERE email = 'YOUR_ADMIN_EMAIL@example.com';
```

لا تضف اختيار دور المدير إلى نموذج التسجيل العام. دور المدير يمنح من لوحة قاعدة البيانات فقط.

## 6. تشغيل محلي (اختياري)

يتطلب Node.js حديثاً. من داخل مجلد المشروع:

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:3000`.

## حدود التكامل الحالية

- قاعدة البيانات تحتوي جداول للفواتير والمدفوعات وتدعم حفظ حالات الدفع، لكن **بوابة دفع فعلية غير مربوطة**؛ يلزم اختيار مزود دفع متاح في بلد ونشاط المنشأة، وإعداد حساب تاجر ومفاتيح سرية وWebhook على خادم آمن.
- جدول المستندات ومساحة التخزين الخاصة وسياسات الملكية موجودة. يلزم ربط شاشة رفع المستندات/إدارتها عند استكمال تلك الواجهة.
- الإشعار داخل قاعدة البيانات يُنشأ عند تقديم طلب أو تغيير حالته. إرسال بريد أو واتساب تلقائي يحتاج مزود رسائل وخدمة خادمية منفصلة.
- يجب مراجعة المتطلبات النظامية وسياسات الخصوصية وشروط تقديم الخدمات قبل استقبال بيانات العملاء الحقيقية.

## أمان

- لا تنشر مفاتيح `service_role` أو مفاتيح الدفع السرية في المتصفح أو GitHub.
- لا تجعل Bucket مستندات العملاء عاماً.
- سياسات RLS جزء أساسي من حماية البيانات، لكنها لا تغني عن مراجعة أمنية واختبار صلاحيات قبل إطلاق الإنتاج.
